المحاضرة التانية كلها عن سؤال واحد: الكمبيوتر بيخزّن بياناته فين، وليه عنده أنواع ذاكرة كتير؟ لأن مفيش ذاكرة بتبقى سريعة + كبيرة + رخيصة في نفس الوقت — فبيستخدموا هرم منهم (Memory Hierarchy). اقلب الكروت دي وشوف كل جزء بيقابل إيه:

الـ Memory Hierarchy 🏔️

الذاكرة مش كلها بنفس السرعة والحجم والتكلفة: فيه سريع وغالي وصغير، وفيه أبطأ وأرخص وأكبر. عشان كده بيستخدموا هرم. الهدف الأساسي: أعلى سرعة ممكنة مع إبقاء تكلفة النظام معقولة.

📖 أول حاجة — إيه هي الـ Computer Memory؟ هي الجزء من الكمبيوتر اللي بيخزّن البيانات والـ instructions والمعلومات. الـ CPU محتاجها لأنه مايقدرش يشتغل من غير ما يوصل لبيانات وinstructions. فكّر فيها كـ مساحة شغل: لما تفتح برنامج بيتحمّل في الذاكرة عشان الـ CPU يشتغل عليه (الداتا بتتحرك من الـ storage للذاكرة، ومن الذاكرة للـ CPU). ومعنى volatile: بيضيّع محتواه لما الكهرباء تتقطع.
👆 اضغط على أي مستوى في الهرم وشوف مواصفاته.
⬇️ قاعدة الهرم (احفظها): كل ما تنزل في الهرم: الـ capacity بتزيد · الـ cost per bit بيقل · الـ speed بتقل. وعكس كده لما تطلع لفوق.

Registers — قمة الهرم

خانات تخزين صغيرة جداً وسريعة جداً جوه الـ CPU. بتشيل البيانات والـ instructions اللي الـ CPU شغال عليها دلوقتي. مثال الملف: 5 + 3 — الرقمين بيتخزّنوا مؤقتاً في registers أثناء الحساب. أسرع ذاكرة، لكن سعتها محدودة جداً.

Cache Memory

ذاكرة صغيرة وسريعة جداً قريبة من الـ CPU أو جواه. بتخزّن البيانات والـ instructions المستخدمة كتير عشان الـ CPU يوصلها بسرعة. ليه محتاجينها؟ لأن الـ CPU أسرع بكتير من الـ main memory، ومن غير cache هيفضل يستنى الـ RAM.

Main Memory (Primary)

بتتكلم مع الـ CPU مباشرة وبتخزّن البرامج والبيانات المستخدمة حالياً. ليها نوعين رئيسيين: RAM و ROM.

Secondary Memory

للتخزين طويل المدى: HDD, SSD, USB flash, memory cards, optical discs, magnetic tape. Non-volatile، أكبر من الـ primary، أرخص بالـ bit، لكن أبطأ من الـ RAM. الـ CPU مابيتعاملش معاه مباشرة.

🧭 لما تفتح برنامج، إيه اللي بيحصل؟ (من الملف)

المسار: Storage ثم RAM ثم CPU. اضغط «الخطوة التالية»:

  1. ① البرنامج متخزّن على الـ SSD أو الـ HDD.
  2. ② الـ operating system بيحمّل الأجزاء المطلوبة منه في الـ RAM.
  3. ③ الـ CPU بيوصل للبيانات عن طريق نظام الذاكرة (memory system).
  4. ④ البرنامج يبدأ ينفّذ (execution).

RAM و ROM 💾

الـ main memory نوعين: RAM (للشغل الجاري، بتضيع لما الكهرباء تقطع) وROM (بتفضل). والـ RAM نفسها نوعين: SRAM وDRAM.

اضغط على أي bit في الـ RAM تقلبه (الـ RAM بتقبل read و write). وجرّب تضغط على bit في الـ ROM 😉

القيم اللي في الخانات أمثلة للتوضيح بس.

Virtual Memory و Paging 🔁

لما الـ RAM تتملي، الـ OS مابيقفش: بيستخدم جزء من الـ SSD/HDD كأنه إضافة للـ RAM. ده الـ virtual memory. وده بيتم عن طريق paging.

Physical Memory

الذاكرة الفعلية المركّبة في الجهاز — غالباً الـ RAM. مكوّن hardware حقيقي تقدر تركّبه أو تشيله.

Virtual Memory

ذاكرة منطقية. مش شريحة RAM إضافية؛ الـ OS بيستخدم جزء من الـ storage (SSD أو HDD) كذاكرة إضافية لما الـ RAM متكفيش.

Physical Memory = Actual RAM  |  Virtual Memory = Technique that uses storage to extend memory
🖥️🗄️ تشبيه الملف: المكتب (RAM) سريع بس صغير. لما يتملي بتنقل كام كتاب مؤقتاً للدولاب (storage اللي بيستخدمه الـ virtual memory). المكتب أسرع، والدولاب بيدّيك مساحة إضافية.

Virtual memory = تقنية إدارة ذاكرة بيوفرها الـ operating system. بتسمح له يستخدم جزء من الـ secondary storage كامتداد للـ RAM لما الذاكرة الفعلية متكفيش. الـ OS ممكن ينقل memory pages من الـ RAM لمنطقة على التخزين اسمها page file أو swap space، وكده بيفضّي RAM لمهام تانية.

⚠️ مهم: الـ virtual memory مابتخلّيش الـ storage سريع زي الـ RAM. التخزين أبطأ بكتير، فالاعتماد الكبير عليها بيقلل الأداء.

الـ virtual memory غالباً بتستخدم paging: الـ OS بيقسّم الذاكرة لبلوكات ثابتة الحجم اسمها pages. لما page تتطلب، الـ OS بيجيبها من التخزين للـ RAM؛ ولو الـ RAM اتملت ممكن بعض الـ pages تترجع للتخزين. العملية دي اسمها paging أو في سياقات معينة swapping.

رسمة الملف: الـ pages بتتحط (mapped) في frames جوه الـ RAM، أو بتفضل على الـ disk في الـ page file. جرّب الرسمة اللي تحت 👇

✅ المزايا

  • بتسمح بتشغيل برامج أكبر من اللي يتّسع في الـ RAM.
  • بتدعم الـ multitasking.
  • بتوفّر memory isolation and protection.
  • بتخلّي الـ OS يستخدم الـ RAM بكفاءة أكبر.

❌ العيب

العيب الأساسي هو الـ performance: القراءة من SSD/HDD أبطأ من الـ RAM. ولو النظام شغّال بينقل pages بين الـ RAM والتخزين باستمرار يبقى بطيء جداً — الحالة دي اسمها thrashing.

💡 More RAM → less dependence on virtual memory → better performance

Page fault

حدث بيتسجّل لما برنامج يوصل لـ page مش موجودة حالياً في الـ RAM. الـ OS بعدها لازم يحمّل الـ page دي من التخزين.

Thrashing

بطء شديد بسبب page faults كتيرة ونقل pages مستمر بين الـ RAM والتخزين. الجهاز بيتبطّأ بشكل درامي.

🧪 جرّب الـ paging

برنامج ليه ٦ pages (P0 … P5) والـ RAM فيها ٣ frames بس. اضغط على أي page عشان البرنامج «يستخدمها». لو مش في الـ RAM هيحصل page fault والـ OS هينقلها — ولو مفيش مكان هيشيل أقدم واحدة. أقدم واحدة = اختيار مبسّط للتجربة

Paging ضد Segmentation

الـ paging مش الطريقة الوحيدة. الـ Segmentation بتقسّم البرنامج لأجزاء منطقية (code, data, stack) متغيّرة الحجم، وده بيطابق طريقة تفكير المبرمج في برنامجه.

🔗 كتير من الأنظمة الحديثة بتجمع الاتنين: البرنامج بيتقسّم لـ segments، وكل segment بيتقسّم لـ pages.

Internal fragmentation

مساحة ضايعة جوه block اتحجز، لأن الـ block أكبر من المطلوب.

External fragmentation

فيه مساحة فاضية كفاية في المجموع، لكنها متقطّعة لقطع صغيرة متفرّقة، فمفيش قطعة واحدة كبيرة كفاية.

🔄 خوارزميات الـ Page Replacement ⭐

لما الـ RAM تتملي ولازم page جديدة تتحمّل، الـ OS لازم يختار ضحية (victim page) يشيلها. الاختيار مهم لأن اختيار وحش = page faults أكتر.

Algorithmالقاعدة (Rule)تعليق الملف (Comment)
FIFORemove the page that entered memory first.Simple, but may remove a page that is still heavily used.
LRURemove the page that has not been used for the longest time.Usually performs well; needs extra tracking hardware.
LFURemove the page used least often.Can keep old pages that were popular in the past.
OptimalRemove the page that will not be needed for the longest time in the future.Gives the best possible result but is impossible to implement — used only as a benchmark.
🧠 لتحفظها: FIFO = الأقدم دخولاً · LRU = الأطول وقت من غير استخدام (في الماضي) · LFU = الأقل استخداماً (في العدد) · Optimal = الأبعد استخداماً في المستقبل (مستحيل تتنفّذ).

الـ Cache Memory ⚡

الـ CPU سريع جداً والـ RAM أبطأ. الـ cache ذاكرة صغيرة وسريعة بين الاتنين بتخلّي الـ CPU يستنى أقل. لكن ليه الفكرة دي بتنجح أصلاً؟ بسبب سلوك البرامج الحقيقية: الـ locality.

CPU → Cache → RAMالـ cache بيقلل وقت الانتظار للـ RAM

① مبدأ الـ Locality of Reference

البرامج مابتوصلش للذاكرة عشوائياً: بتعيد استخدام نفس البيانات وبتوصل لبيانات قريبة من بعض.

Temporal locality — في الزمن

لو مكان في الذاكرة اتستخدم دلوقتي، غالباً هيتستخدم تاني قريب. مثال الملف: متغيّر counter جوه loop.

Spatial locality — في المكان

لو مكان اتستخدم، الأماكن القريبة منه غالباً هتتستخدم قريب. مثال الملف: قراءة عناصر array واحد ورا التاني.

💡 بسبب الـ locality، تخزين كمية صغيرة من البيانات اللي اتستخدمت حديثاً في cache سريع بيخدم الأغلبية الساحقة من طلبات الذاكرة. ده السبب الكامل اللي بيخلّي الـ memory hierarchy تشتغل.

🧪 مثال: sum += a[i] في loop للتوضيح — حجم الـ block = ٤ من اختياري

الـ array فيه ٨ عناصر، مقسّمة لـ block لونه مختلف (الـ cache بيجيب block كامل لما يحصل miss — من الملف). اضغط «التكرار التالي»:

② Hit و Miss و Hit Ratio

Cache Hit

الداتا موجودة في الـ cache، فبتتسلّم بسرعة كبيرة.

Cache Miss

الداتا مش موجودة، فلازم يتجاب block كامل من الـ main memory، وده أبطأ بكتير.

Hit Ratio = Number of hits ÷ Total number of accesses
Average Access Time = (Hit Ratio × Cache Time) + (Miss Ratio × Memory Time)
📐 مثال الملف: Cache = 2 ns · Main memory = 100 ns · Hit ratio = 0.9. والنتيجة: (0.9 × 2) + (0.1 × 100) = 1.8 + 10 = 11.8 ns. حتى hit ratio ٩٠٪ بيخلّي الذاكرة أسرع حوالي ٨ مرات من الـ RAM لوحدها، ولو رفعنا الـ hit ratio لـ 0.99 المتوسط ينزل لحوالي ٣ ns.

Compulsoryالـ block بيتوصل له لأول مرة؛ مكانش ممكن يكون في الـ cache أصلاً.

④ الـ Cache Mapping

الـ main memory أكبر بكتير من الـ cache، فلازم قاعدة تحدد الـ block ممكن يتحط فين جوه الـ cache. فيه ٣ طرق كلاسيكية:

كل memory block يروح cache line واحد بس، بيتحدد بحساب بسيط. أبسط وأرخص scheme والبحث سريع جداً، لكن بيعاني من conflict misses لما block نشطين يتحولوا لنفس الـ line.

🧠 فهم عام (الملف مادّاش الصيغة): الحساب المعتاد line = block mod (number of lines) — هنستخدمه في المحاكي اللي تحت.

الـ block ممكن يتحط في أي cache line. أحسن مرونة وأقل conflict misses، لكن البحث محتاج مقارنة tags كتير في نفس الوقت، وده بيخلّي الـ hardware غالي.

حل وسط: الـ cache مقسّم لـ sets، والـ block بيروح set واحد لكن ممكن يقعد في أي line جواها. cache وصفه 4-way set associative معناه ٤ lines في كل set. ده اللي بتستخدمه أغلب المعالجات الحقيقية.

TechniqueFlexibilityHardware costConflict misses
DirectLowLowHigh
Set-associativeMediumMediumMedium
Fully associativeHighHighVery low

🧪 محاكي الـ mapping cache = ٤ lines · للتوضيح

اكتب أرقام الـ blocks بالترتيب اللي الـ CPU بيطلبها، وشوف الـ 3 طرق بيعملوا إيه. (Set-associative هنا = 2-way: set لكل ٢ line، والاستبدال جوه الـ set أو الـ cache = LRU — اصطلاح للمحاكي مش من الملف.)

لاحظ في 0 4 0 4 0 4: الـ block 0 و 4 بيتحوّلوا لنفس الـ line في الـ direct (conflict miss في كل مرة)، بينما الـ fully associative و 2-way بيحتفظوا بالاتنين.

⑤ الـ Write Policies

لما الـ CPU يكتب داتا، لازم الـ cache والـ main memory يتّفقوا في الآخر. سياستين:

Write-Through

الداتا بتتكتب في الـ cache والـ main memory في نفس الوقت. الذاكرة دايماً متّسقة (consistent)، لكن الكتابة أبطأ.

Write-Back

الداتا بتتكتب في الـ cache بس، وبتتنسخ للـ main memory بعدين لما الـ line تتبدّل. أسرع، لكن محتاجة dirty bit عشان تعلّم الـ lines المعدّلة.

التخزين HDD · SSD · Flash 💿

الـ secondary storage هو اللي بيحتفظ بالبيانات على المدى الطويل (non-volatile). أشهر نوعين: HDD (فيه حركة ميكانيكية) و SSD (من غير حركة). وفضلنا فاكرين: الـ CPU مابيشتغلش مباشرة على الـ disk — البيانات بتتحمّل للـ RAM الأول.

HDD = Hard Disk Drive: جهاز تخزين مغناطيسي جواه platters بتلف وread/write heads بتتحرك. البيانات متنظّمة في tracks و sectors، والـ head بيتحرك على الـ platter عشان يوصل لها. ولأن فيه أجزاء بتتحرك ميكانيكياً، الوصول للبيانات فيه تأخيرات ميكانيكية.

⏱️ Disk Access Time — ٣ تأخيرات

الرسمة توضيحية مبسطة (الـ head بيتحرك بشكل مستقيم عشان تشوف الفكرة).

DelayMeaning
Seek TimeTime required to move the read/write head to the required track.
Rotational LatencyTime required for the desired sector to rotate under the head.
Transfer TimeTime required to actually transfer the data.
Disk access = Seek + Rotate + Transferالملف بيقول ٣ تأخيرات — مفيش معادلة بأرقام، بس الفكرة إنهم بيتجمعوا

SSD = Solid-State Drive: بيستخدم NAND flash memory وعنده مفيش أجزاء ميكانيكية متحركة. ده بيدّيه مزايا:

  • أسرع في الوصول (Faster access)
  • تأخير ميكانيكي أقل (Lower mechanical latency)
  • استهلاك طاقة أقل في كتير من أحمال الشغل (Lower power consumption in many workloads)
  • مقاومة أحسن للصدمات الفيزيائية (Better resistance to physical shock)
  • هادي (Quiet operation)
💡 عشان كده الكمبيوترات الحديثة غالباً بتستخدم SSD بدل HDD كتخزين أساسي. SSD سريع لأنه من غير أجزاء متحركة، والـ HDD بيستخدم أجزاء ميكانيكية للوصول للبيانات.

الـ SSD والـ USB drives مبنيين من NAND flash، وهو شكل من EEPROM. الـ flash ليه خصائص تخلّيه يتصرف مختلف عن الـ RAM وعن الـ disks المغناطيسية:

  • الـ flash متنظّم في pages (بتتكتب) متجمّعة في blocks (بتتمسح). الـ page مايتنفعش تتكتب فوقها مباشرة — لازم الـ block كله يتمسح الأول.
  • كل cell بتتحمّل عدد محدود من دورات المسح، فالـ flash ليه finite endurance.
  • Wear levelling: بيوزّع الكتابة بالتساوي على كل الـ blocks عشان مفيش منطقة تتهلك بدري.
  • TRIM command: بيخلّي الـ OS يقول للـ SSD إيه الـ blocks اللي مابقتش مستخدمة، فالـ drive ينضّفها مقدماً ويفضل سريع.
  • الـ controller جوه الـ SSD بيدير الـ mapping والـ wear levelling وتصحيح الأخطاء والـ caching — وده سبب كبير إن SSDين بنفس الـ flash ممكن يختلف أداؤهم جداً.

RAID 🧱

RAID = Redundant Array of Independent Disks: بيجمّع أكتر من drive فيزيائي في وحدة منطقية واحدة لتحسين الأداء أو الموثوقية أو الاتنين.

LevelTechniqueBenefit / Risk
RAID 0Striping — data split across disksFastest, full capacity, but one failed disk loses everything.
RAID 1Mirroring — identical copy on two disksExcellent protection; usable capacity is halved.
RAID 5Striping with distributed parityGood balance of speed, capacity and fault tolerance; survives one disk failure.
RAID 6Striping with double paritySurvives two simultaneous disk failures.
RAID 10Mirroring plus stripingHigh speed and high reliability at high cost.
🚫 RAID مش backup! بيحميك من تعطّل الـ hardware بس، مش من الحذف أو التلف أو الـ malware. الـ backup الحقيقي لازم يكون نسخة منفصلة.

⏳ الفرق بين مستويات الأداء (Typical access times — مقياس لوغاريتمي)

من جدول الملف (تقريبي): Register: well under 1 ns · L1: about 1 ns · L2/L3: a few to tens of ns · DRAM: roughly 50 - 100 ns · NVMe SSD: tens of µs · HDD: several ms. الأشرطة بتوضّح المدى التقريبي فقط (الارتفاع مش دقيق). «الفرق بين أسرع وأبطأ مستوى بيمتد على عدة أوامر قدر (orders of magnitude)» — ده السبب إن الـ hierarchy والـ cache والـ locality مهمين جداً.

🔀 Memory Interleaving

حتى مع الـ caches، الـ main memory ممكن تفضل تعطّل الـ CPU. الـ interleaving بتقسّم الـ main memory لـ عدة banks (modules) مستقلة، بحيث العناوين المتتالية تقع في banks مختلفة. لأن الـ banks بتشتغل في نفس الوقت، النظام يقدر يبدأ access جديد في bank بينما bank تاني لسه بيخلّص access سابق — وده بيخبّي جزء كبير من الـ memory cycle time.

Low-order interleaving

الـ least significant address bits هي اللي بتختار الـ bank، فالعناوين المتتالية بتتوزّع على كل الـ banks. ممتاز للـ sequential access (قراءة array أو fetch لـ cache block).

High-order interleaving

الـ most significant bits هي اللي بتختار الـ bank، فكل bank بيشيل منطقة متصلة من الذاكرة. مناسب لموديولات مستقلة لكن مفيش تسريع للقراءة المتتابعة.

🧪 قارن بنفسك ٤ banks · ١٦ address · زمن كل access = ٤ وحدات (من اختياري)

الوقت الكلي — Low-order
الوقت الكلي — High-order

كل صف = bank، وكل مربع ملوّن = وقت انشغال الـ bank بـ access. في الـ low-order الـ banks بتشتغل متداخلة؛ وفي الـ high-order العناوين المتتالية بتنزل على نفس الـ bank فبتستنى بعض. التقريب ده مبسّط (بدأت access جديد كل وحدة زمن لو الـ bank فاضي).
